# SDK 导读（智能体入口）

> 你好。如果你是 AI 智能体（DeepSeek Harness / 其他），读到这个包时按本导读理解。

## 这个 SDK 是什么

一套**图色自动化系统的工程化实现骨架**。不是针对某个游戏的工具，是"怎么从零搭图色自动化"的方法论 + 参考代码。

换任何游戏，按这套骨架走，能搭出能跑的自动化。

## 包结构

```
自动化系统SDK/
├── SDK导读.md            ← 你正在读
├── 架构总览.md            ← 4层架构 + 流水线 + 5步法（先读这个）
├── 接口契约.md            ← 层间传什么数据（最核心，必读）
├── 换游戏改动清单.md       ← 换游戏时只改感知层
├── drivers/
│   └── interception.dll  ← 驱动级键鼠注入（需管理员）
├── perception/           ← 感知层（看）
│   ├── find_window.py    ← 找窗口拿句柄
│   ├── grab_frame.py     ← 抓客户区画面
│   └── find_targets.py   ← 色块连通域识别
├── decision/             ← 决策层（脑）
│   └── decision_engine.py ← 选目标+锁定击杀
├── action/               ← 执行层（手）
│   └── mouse_inject.py   ← Interception 驱动级点击
├── check/                ← 校验层
│   └── motion_check.py   ← 帧差校验防卡死
├── support/              ← 支撑层
│   └── calibrate.py      ← 标定 px_per_cell + 坐标换算
└── system/               ← 系统层
    ├── config_manager.py ← 配置管理
    ├── error_handler.py  ← 异常恢复
    └── hotkey_stop.py    ← 热键急停
```

## 怎么用这个包

### 场景1：帮用户从零搭自动化

1. 读 `架构总览.md` 理解 4 层架构
2. 读 `接口契约.md` 知道层间传什么
3. 按 `perception → decision → action → check → system` 顺序，每层一个文件实现
4. 每层实现完单独测，不要堆着做
5. 最后写主循环串起来

### 场景2：换游戏

1. 读 `换游戏改动清单.md`
2. **只改感知层**（颜色阈值/形状/标定）+ config 一处
3. 决策/执行/校验/系统层不动

### 场景3：分析现有自动化脚本的 BUG

1. 读 `架构总览.md` 理解标准架构
2. 把现有代码对照 4 层归类
3. 检查违反了哪条工程化原则（单一职责/接口契约/独立测试）
4. BUG 通常出在层间接口对不上，不在层内部

## 核心原则（必须遵守）

1. **单一职责**：每层只做一件事，不越界
2. **接口契约**：层间用数据结构通信，不传上下文
3. **独立测试**：每层能单独验证，不依赖其他层
4. **配置与逻辑分离**：参数进 config.json，不硬编码
5. **精度管好不好用，契约管崩不崩**——这是两个不同的事

## 技术依赖

- Python 3.12+
- numpy + Pillow + scipy
- Windows（用了 ctypes 调 Windows API）
- Interception 驱动（drivers/interception.dll，需管理员）

## 不包含的（要自己补）

- 具体游戏的颜色阈值（要采样真实画面）
- A*寻路 + 壁障图（决策层的高级功能，本 SDK 只做选目标）
- 模板匹配 / OCR（感知层的高级功能，本 SDK 只做色块识别）
- 面板 GUI（系统层只做了配置/异常/热键，没做 tkinter 面板）
- 键盘注入（执行层只做了鼠标）

这些是"填充"项，按需补——不影响骨架跑起来。
