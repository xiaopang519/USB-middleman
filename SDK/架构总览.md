# 架构总览

## 图色自动化系统的本质

一条循环流水线：

```
找窗口 → 抓画面 → 识别（找目标）→ 决策（打谁/走哪）→ 执行（点/按）→ 校验（防卡死）→ 回到抓画面
```

不管什么游戏，拆开来都是这条流水线。

## 4 层架构

| 层 | 职责 | 本 SDK 文件 | 输入 | 输出 |
|---|---|---|---|---|
| 感知层（看） | 找窗口、抓帧、找目标 | perception/ | 句柄/图像 | 目标列表 |
| 决策层（脑） | 选目标、锁定击杀 | decision/ | 目标列表 | 单个目标或None |
| 执行层（手） | 鼠标移动+点击 | action/ | 屏幕坐标 | 硬件事件注入 |
| 校验层 | 帧差判断动没动 | check/ | 前后两帧 | bool |
| 支撑层 | 标定+坐标换算 | support/ | 像素坐标 | 格子坐标 |
| 系统层 | 配置/异常/热键 | system/ | - | - |

## 数据流向

```
[感知层] → 目标列表 [{"cx":int, "bar_y":int, "bar_w":int}, ...]（客户区坐标）
    ↓
[决策层] → 单个目标 {"cx", "bar_y", "bar_w"} 或 None
    ↓
[执行层] → 屏幕坐标 (x, y) → 鼠标注入
    ↓
[校验层] → bool（动没动）→ 没动则触发突围
```

支撑层贯穿全程（坐标换算），系统层也贯穿全程（配置/异常/热键）。

## 工程化 5 步法

做任何项目按这 5 步走：

1. **画分层图** — 哪层干啥
2. **定接口契约** — 层间传什么数据（见 `接口契约.md`）
3. **写 stub** — 空壳对得上接口，没实现
4. **逐层实现 + 单独测** — 每层独立验证
5. **集测** — 拼起来跑全集

**跳第 2 步（接口契约）= 补数据时数据和逻辑对不上 = 爆 BUG。**

## 脚本三职责

脚本（主循环）= 初始化 + 主循环 + 兜底：

- **初始化**：加载配置、找窗口、建驱动上下文（循环跑之前）
- **主循环**：while True: 感知→决策→执行→校验（循环里）
- **兜底**：热键急停、异常捕获、卡死突围（出事时）

## 关键认知

1. **感知层不可能"完全感知"** — 图色识别天生不完美。自动化不靠感知完美，靠决策层兜住偏差。
2. **精度管好不好用，契约管崩不崩** — 漏几只怪=效率低（不崩）；坐标格式对不上=崩。
3. **画面中心=角色位置** — 俯视角游戏角色永远在画面中心。
4. **驱动级注入穿透游戏保护** — SendInput 合成输入会被挡，Interception 从驱动层注入。
