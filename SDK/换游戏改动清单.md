# 换游戏改动清单（SDK 版）

> 换游戏时照这份改，不用读全部代码。
> 原则：**只改感知层 + 配置一处，其余层不动。**

## 一、要改的

### 1. 找窗口关键字 — 配置

| 位置 | 改什么 |
|---|---|
| `config.json` 的 `game_keyword` | 改成新游戏窗口标题里的关键字 |

只改 config.json，不改代码。

### 2. 目标颜色阈值 — 感知层（改动最大）

| 位置 | 改什么 |
|---|---|
| `perception/find_targets.py` 顶部 `R_MIN/G_MAX/B_MAX` | 改成新游戏目标的颜色范围 |

**怎么定新阈值**：
1. 跑 `perception/grab_frame.py` 抓一帧 → `frame.png`
2. 从画面里采样目标像素，打印 R/G/B 范围
3. 填回 `find_targets.py` 的阈值

### 3. 目标形状过滤 — 感知层

| 位置 | 改什么 |
|---|---|
| `perception/find_targets.py` `MAX_BAR_H` | 目标最大高度 |
| `perception/find_targets.py` `MIN_BAR_RATIO` | 宽/高 最小比例 |
| `perception/find_targets.py` `Y_MAX` | 扫描区域（目标在画面哪部分） |

### 4. 坐标标定 — 支撑层

| 位置 | 改什么 |
|---|---|
| `support/calibrate.py` | 用走步法重新标定 `px_per_cell` |

走步法：角色走 N 格，量参照物像素位移，`px_per_cell = 像素位移 ÷ 格子位移`。

### 5. 决策策略参数 — 决策层（可能微调）

| 位置 | 默认值 | 换游戏要不要改 |
|---|---|---|
| `decision/decision_engine.py` `DEAD_TIMEOUT` | 1.5秒 | 目标闪得厉害就调大 |
| `decision/decision_engine.py` `STUCK_TIMEOUT` | 45秒 | 打得慢就调大 |
| `decision/decision_engine.py` `CX/CY` | 640/512 | 换分辨率要改 |

## 二、不动的

| 层 | 文件 | 为什么不动 |
|---|---|---|
| 执行层 | `action/mouse_inject.py` | Interception 注入，和游戏无关 |
| 校验层 | `check/motion_check.py` | 帧差法，和游戏无关 |
| 系统层 | `system/config_manager.py` | 配置管理通用 |
| 系统层 | `system/error_handler.py` | 异常恢复通用 |
| 系统层 | `system/hotkey_stop.py` | 热键通用 |

## 三、操作顺序（每步单独验证）

```
1. 改 config.json 的 game_keyword
   → 跑 perception/find_window.py 验证：能找到新游戏窗口吗？

2. 跑 perception/grab_frame.py 抓一帧
   → frame.png 是新游戏画面吗？

3. 采样新目标颜色，改 perception/find_targets.py 阈值
   → 跑 find_targets.py 验证：识别到合理数量吗？

4. 走步法重新标定 px_per_cell
   → 跑 support/calibrate.py 验证：换算的格子坐标对吗？

5. 集测（写主循环串起来）
   → 能锁定目标 + 点击 + 不崩
```

## 四、核心原则

**感知层是换游戏时的全部工作量。** 决策/执行/校验/系统层都不动——这就是分层的回报。

换游戏时如果要改决策层或执行层，说明那层和游戏耦合了（违反接口契约），要回头解耦。
